# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и оформления покупки, обеспечивая полный цикл покупки с отправкой заказа на сервер.

---

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает разделение ответственности между слоями:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - слой логики, связывает данные и представления и обрабатывает события.

Взаимодействие между классами обеспечивается событийной моделью:
- View сообщает о действиях пользователя → событие
- Presenter принимает решение → вызывает методы моделей
- Model эмитит событие `*:changed` → Presenter рендерит View на основе моделей

Важно: модели не передают данные в событиях. Событие сообщает только факт изменения, а актуальные данные презентер получает через методы моделей (`getItems`, `getPreview`, `get`, `getCount` и т.д.).

# Базовый код

## Класс Component

Базовый класс для всех UI-компонентов.  
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент, за отображение которого отвечает компонент.

Поля класса:  
`container: HTMLElement` - корневой DOM элемент компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - главный метод класса. Он принимает данные, записывает их в поля через сеттеры и возвращает DOM элемент компонента.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`.

## Класс Api

Содержит базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})`

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - заголовки запросов

Методы:  
`get(uri: string): Promise<object>` - GET запрос  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - POST запрос  
`handleResponse(response: Response): Promise<object>` - защищенный метод для проверки ответа сервера

## Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяя отправлять события и подписываться на события в системе.  
Используется для связи слоя данных и представления.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>` - хранит подписки на события.

Методы класса:  
`on(event, callback)` - подписка на событие  
`emit(event, data?)` - генерация события  
`trigger(event, context?)` - генератор обработчика события

# Модели данных

Модели данных реализованы в виде отдельных классов, каждый отвечает за хранение и обработку определённой группы данных.  
Модели независимы и не зависят от визуальных компонентов.

## Класс ProductModel

Зона ответственности: хранение каталога товаров и выбранного товара для просмотра.

Поля:
- `items: IProduct[]` - массив всех товаров
- `preview: IProduct | null` - выбранный товар для превью

Методы:
- `setItems(items: IProduct[]): void` - сохраняет массив товаров и эмитит `catalog:changed`
- `getItems(): IProduct[]` - возвращает каталог
- `setPreview(product: IProduct | null): void` - сохраняет товар для превью и эмитит `preview:changed`
- `getPreview(): IProduct | null` - возвращает товар для превью

События модели:
- `catalog:changed`
- `preview:changed`

## Класс CartModel

Зона ответственности: хранение товаров корзины.

Поля:
- `basket: IProduct[]` - товары в корзине

Методы:
- `getItems(): IProduct[]` - возвращает товары корзины
- `addItem(product: IProduct): void` - добавляет товар в корзину и эмитит `basket:changed`
- `removeItem(id: string): void` - удаляет товар и эмитит `basket:changed`
- `clear(): void` - очищает корзину и эмитит `basket:changed`
- `getTotal(): number` - возвращает общую стоимость
- `getCount(): number` - возвращает количество товаров
- `has(id: string): boolean` - проверяет наличие товара в корзине

События модели:
- `basket:changed`

## Класс BuyerModel

Зона ответственности: хранение данных покупателя и их валидация.

Поля:
- `data: Partial<IBuyer>` - частично заполненные данные покупателя

Методы:
- `set(partial: Partial<IBuyer>): void` - сохраняет поля и эмитит `buyer:changed`
- `get(): Partial<IBuyer>` - возвращает данные
- `clear(): void` - очищает данные и эмитит `buyer:changed`
- `validate(): BuyerValidationErrors` - проверяет заполненность полей
- `validatePaymentStep(): BuyerValidationErrors` - проверяет только `payment + address`
- `validateContactsStep(): BuyerValidationErrors` - проверяет только `email + phone`

События модели:
- `buyer:changed`

# Слой коммуникации - Класс ShopApi

Зона ответственности: взаимодействие приложения с сервером.  
Класс реализует запросы к API для получения каталога товаров и оформления заказа.  
Использует композицию с базовым классом `Api`.

Конструктор:  
`constructor(api: Api)` - принимает экземпляр базового `Api`.

Методы:
- `getProducts(): Promise<IProduct[]>` - GET /product/
- `order(order: IOrderRequestApi): Promise<IOrderResponse>` - POST /order

При отправке заказа поле `payment` преобразуется из 'card' в 'online', чтобы соответствовать требованиям API.

# Классы слоя представления (View)

Классы представления отвечают только за отображение данных и генерацию событий.  
View не хранит данные товара/покупателя, все данные приходят из моделей через презентер.

Основные правила:
- все DOM элементы находятся в конструкторе и сохраняются в поля
- все слушатели событий устанавливаются один раз в конструкторе
- view не содержит методов get... и не предоставляет данные наружу
- формы и карточки обновляются только через `render()`

## Header

Зона ответственности: кнопка корзины и счётчик товаров.

Сеттеры:
- `count: number` - отображает количество товаров

События:
- генерирует `basket:open` при клике на кнопку корзины

## Gallery

Зона ответственности: контейнер каталога на главной странице.

Сеттеры:
- `items: HTMLElement[]` - отображает список карточек каталога

## Modal

Зона ответственности: оболочка модального окна.  
Открывает любой HTML элемент как контент.

Функциональность:
- закрытие по клику на overlay
- закрытие по крестику

# Карточки товаров

Используются разные карточки для разных отображений:
- `CatalogCard` - карточка каталога (`#card-catalog`)
- `PreviewCard` - карточка превью (`#card-preview`)
- `BasketCard` - карточка товара в корзине (`#card-basket`)

Особенности:
- категории оформляются через `categoryMap` из `src/utils/constants.ts`
- если цена null - кнопка покупки disabled и текст "Недоступно"
- кнопка в превью меняется "Купить" / "Удалить" / "Недоступно", исходя из данных презентера

События:
- `CatalogCard` вызывает `onSelect()` → презентер эмитит `card:select`
- `PreviewCard` вызывает `onClick()` → PreviewCard эмитит `preview:action` → `Presenter` по данным `(cartModel.has)` решает add/remove
- `BasketCard` вызывает `onRemove()` → презентер эмитит `product:remove:basket`

## Basket

Зона ответственности: отображение корзины.

Сеттеры:
- `items: HTMLElement[]` - список карточек
- `total: number` - итоговая сумма
- `canOrder: boolean` - активность кнопки оформления

События:
- генерирует `order:open` при клике на "Оформить"

Если корзина пуста, список очищается и внутри `.basket__list` отображается текст "Корзина пуста".

# Формы заказа

Формы реализованы как 2 отдельных компонента:
- `OrderPaymentForm` - шаг 1 (`#order`) выбор оплаты + адрес
- `OrderContactsForm` - шаг 2 (`#contacts`) email + phone

Обе формы:
- эмитят `form:change` при изменении полей (`field`, `value`)
- имеют кнопку submit, активность которой управляется через `canSubmit`
- отображают ошибки через объект `errors`

События:
- `OrderPaymentForm` эмитит `order:submit`
- `OrderContactsForm` эмитит `contacts:submit`

Окно успешной оплаты (`#success`).  
Отображает итоговую сумму `total`.

События:
- генерирует `success:close` при клике на "За новыми покупками"

# События приложения

## События моделей (Model → Presenter)
- `catalog:changed` - обновился каталог товаров
- `preview:changed` - выбран/изменён товар для превью
- `basket:changed` - изменилось содержимое корзины
- `buyer:changed` - изменились данные покупателя

## События представления (View → Presenter)
- `basket:open` - открыть корзину
- `card:select` - открыть товар (id)
- `product:remove:basket` - удалить товар из корзины (id)
- `order:open` - открыть оформление заказа
- `order:submit` - отправка первого шага формы (payment + address)
- `contacts:submit` - отправка второго шага формы (email + phone)
- `form:change` - изменение поля формы (field, value)
- `success:close` - закрыть success и вернуться к покупкам

# Презентер (main.ts)

Презентер реализован в `src/main.ts` и состоит из обработчиков событий.

Основная логика:
- загрузка каталога через `ShopApi.getProducts()` и сохранение в `ProductModel`
- рендер каталога при `catalog:changed`
- выбор карточки `card:select` → `productModel.setPreview()`
- открытие превью при `preview:changed`
- добавление/удаление товара из превью (решение принимает презентер)
- обновление счётчика корзины при `basket:changed`
- открытие корзины при `basket:open`
- удаление товара из корзины по событию `product:remove:basket`

Оформление заказа:
- `order:open` - открытие формы оплаты (payment + address)
- `order:submit` - валидация `validatePaymentStep()` и переход к форме контактов
- `contacts:submit` - валидация `validateContactsStep()`, сбор заказа, отправка на сервер
- success - показ окна успеха и очистка корзины/покупателя
- `success:close` - закрытие модального окна

# Соответствие функциональным требованиям

- Каталог товаров отображается на главной странице
- При клике по карточке открывается модалка с превью товара
- Корзина открывается по клику на иконку корзины
- На иконке отображается счетчик товаров
- В превью доступна покупка/удаление товара
- Если у товара нет цены - кнопка disabled и "Недоступно"
- В корзине отображается список товаров, сумма, удаление, нумерация
- Если корзина пуста - выводится "Корзина пуста", оформление disabled
- Оформление заказа в два шага:
  - шаг 1: payment + address
  - шаг 2: email + phone
- Валидация шаговая и корректная
- После оплаты показывается Success, корзина и buyer очищаются
- Модалки закрываются по клику на overlay и по крестику
- Модалки не скроллятся
